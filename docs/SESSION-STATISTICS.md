# Private practice sessions and daily totals

Implemented 2026-10-17. Profile → **Practice sessions and daily totals / 练习时段与每日汇总** opens owner-only statistics from the current regional database. Shared profiles continue to expose only their separately authorized aggregate category counts and personal bests; session dates and timing are never added to shared responses.

`GET /v1/me/session-statistics?timeZone=Asia%2FShanghai` accepts only a named time zone, defaults to UTC and rejects unknown query fields. Authentication, regional boundaries and private/no-store headers apply. Sixty requests per account/minute are allowed. The query reads at most 1,001 approved race/daily records, ordered by creation time and ID, and computes statistics over the newest 1,000. A composite owner/status/date/ID index supports this query. No move streams, scrambles, evidence, nonces, other accounts or profile names are fetched or returned.

Only approved race/daily solves with positive server durations of at most one hour contribute. Rejected, provisional, incomplete and pattern/sprint/relay attempts do not count. Physical results retain their existing approval requirements. Puzzle and input categories remain separate for solve counts, best time, arithmetic mean and accumulated solving time. These are personal server-timed records, not official competition results, turning-speed measurements or official averages including failed attempts.

Sessions are computed in chronological start order. A gap of more than thirty minutes from the previous session's latest solve end starts a new session. Exactly thirty minutes stays in the same session. Sessions can cross midnight and daylight-saving changes. Session span includes gaps; accumulated solving time is the sum of durations and is separately labeled. Historical records without a start timestamp use their creation timestamp, with an explicit estimate count shown in the app. A missing or inconsistent finish timestamp falls back to start plus duration.

Daily totals group each solve by its start date in the requested named zone, with the same historical fallback. The app reads its device's configured zone and offers UTC; this requires no location permission, does not change the community and does not persist a new timezone preference on the server. The request contains the zone name, which ordinary operational logs may capture; operators should keep query logs minimal under their regional retention policy. No AI or external time-zone service is used.

The response returns the latest thirty sessions and thirty active dates in the selected window, disclosing omitted counts and whether earlier records exist. The oldest selected session is marked potentially incomplete when the history window is truncated. Daily counts also reflect only this window. Empty histories produce an empty state. Results are not cached offline. The mobile screen clears data on account/community/time-zone/navigation changes and ignores responses from an earlier view.

Statistics are derived, not separately stored: normal account export includes the underlying owned attempts, and account deletion removes access and source records under the existing deletion policy. No new sharing permission is introduced. Pending child accounts can inspect their own records without acquiring learning, recording, public-profile or community access.

Unit checks cover midnight, exact/over-threshold gaps, daylight-saving changes, category separation, legacy timestamps, omitted history, invalid zones and input bounds. Database/API checks cover ownership, authentication, unknown fields, cross-region denial, privacy headers, excluded attempts, 1,000-record windows and account deletion. Regional Docker checks exercise the actual compiled API after database restart. Native bundles establish build integration; physical-device, accessibility and fresh visual QA remain required.
