# Bilingual course authoring and revisions

The admin Learning library now connects to persistent regional course editing. ADMIN accounts with a current MFA session can create original drills, edit teaching, inspect recent revisions, restore earlier text as a new draft, and publish/withdraw an exact saved revision. MODERATOR accounts can inspect material but cannot create, edit or publish it. These are authored learning features; mainland social/game operating gates remain separate and unchanged.

## Authoring

New drills receive a server-generated custom UUID identity and start unpublished. Choose 2×2, 3×3, 4×4 or Pyraminx, level, English/Chinese title, introduction and steps, a move sequence and suggested time. Both languages must contain actual text. The server bounds titles, paragraphs, total serialized teaching, sequence length and duration; verifies notation against the selected puzzle; and reconstructs the inverse setup followed by the submitted exercise. Empty/identity exercises, impossible notation, more than 500 turns, forged course identities and new unverified guided/case methods are rejected. A valid sequence is not by itself proof that the teaching is accurate: an administrator must inspect the original instruction and intended audience before publishing.

For the 149 built-in lessons, puzzle, level, method, case family and verification sequence remain tied to the tested core curriculum. Their bilingual wording, paragraphs and suggested time can be revised. Different sequences belong in new original drills, rather than silently changing compiled placement tasks, recognition or guided checkpoint methods. Specialized guided-stage explanations and placement/recognition definitions remain versioned core source, separate from the editable Course introduction/teaching record. A saved custom course also keeps its puzzle identity; create a separate course for another puzzle. Smart-cube input remains unavailable pending its separate integration/physical acceptance.

All writes are rate limited to sixty per staff account per hour, and the region has a serialized maximum of 1,000 custom courses. Request size and text/notation limits also apply. The catalogue searches either title or identity with literal wildcard escaping, pages thirty records at a time and supports up to 150 visible matches before requiring a narrower search. Cursors are validated course identities used as lexical boundaries; they survive deletion of that boundary. Draft material remains behind regional staff/MFA authorization.

## Save, review and publish

Editing requires the exact current version. Saving a substantive edit increments it and withdraws the published lesson into a draft; concurrent/stale writes return a conflict. A structural no-op leaves the version/publication unchanged. The editor explains withdrawal before saving. Read both saved language previews, confirm English review, Chinese review and content rights/accuracy/audience suitability, then publish that exact revision. These are staff attestations, not automated copyright or legal approval. Withdrawal does not require falsely affirming a review.

Publishing and withdrawal increment the version, so content and availability transitions are explicit. Create/edit/publish audit events use the current staff actor, version, bounded edit reason and normalized content digest. Do not put learner personal data or contact lists in course teaching or reasons. Actual operator authorship/licensing, moderation policy and applicable AI provenance disclosures remain release responsibilities.

The database retains at most fifty recent course snapshots, with version, teaching, publication state, time and digest. Metadata listing does not return all teaching snapshots at once. Earlier content can be loaded into the editor, then saved as a **new** version; historical snapshots are never overwritten by restore. A revision snapshot has no staff actor identifier or edit reason; those stay in the ordinary bounded staff audit trail. Snapshots are a recent editorial history, not a permanent archive or database backup.

The UI rejects late account/view responses, clears the editor on backgrounding, resets review confirmations when content changes, focuses the opened editing form and uses separate saved/current versus proposed historical content. Unsaved edits cannot publish a different record by accident. Browser access remains denied in this session, so fresh rendered/interaction acceptance has not been claimed.

## Learner progress and stale content

Virtual drill completion, physical-session creation and tutoring require the revision loaded by the learner. Practice completion/scan checkpoints take a shared course lock and recheck current publication/version before committing. The tutor checks before generation and again afterward without holding a database transaction across the provider wait. Concurrent editing/withdrawal cannot turn an old sequence or explanation into progress for a newer lesson. Guided first-solve checks also hold current course/version references while committing.

Progress now records the verified course version. `completed` retains historical practice; `currentCompleted` means the same revision is currently published. Learning cards/counts use current completion, and adaptive queues do not treat an earlier edition as completion of the latest edition. Existing historical milestones and repetition records are retained, and completed sessions retain their puzzle, moves, algorithm and version. Repeating a revised exercise updates the current verified version rather than rewriting the old session. This does not preserve every historical course description indefinitely.

The additive migration backfills versions only from completed saved drill/guided records. Legacy unknown records remain explicitly unversioned; old empty-move guided shortcuts are not treated as validated guided completion. Current-completion marks may therefore differ from historical counts. Existing session/history and account exports preserve that distinction without inventing new credit.

Mobile lesson views refresh on navigation focus and clear account/permission context changes. Physical practice resumes only a matching course revision. Online download manifests remove old/withdrawn editions under the existing offline policy; an offline device can retain its issued teaching lease for up to 24 hours and cannot earn offline credit. Saving a draft does not remotely recall an existing offline copy or already-viewed material.

## Shorter sequence options

The editor can load the packaged [shorter alternatives](LESSON-ALTERNATIVES.md) for review while retaining the original setup and case identity. Both languages and the chosen turns are visible before saving. Legacy lessons may omit the optional field. Saving a changed option withdraws publication and advances the version; publication retains current administrator MFA and explicit bilingual/rights checks. Old sessions keep their course version, original setup, actual moves and selected-guide snapshot. Normal seeding never overwrites existing content.
