# Independent media decisions during recovery

Implemented 2026-10-18. The current encrypted privacy journal now covers individual file erasure, evidence-retention decisions and guardian consent withdrawal as well as account deletion. These decisions replay before API/worker startup and during maintenance. They also replay into the sealed database-restore stage. Encrypted S3 capture, isolated restoration and [recurring current-object/key expiry](MEDIA-MAINTENANCE.md) are now connected. **Safe history pruning, provider/alert acceptance and complete recovery commissioning remain unfinished.** Restores remain sealed and public release remains gated.

## Durable decisions and exact ownership

A version-2 event is encrypted and entered in the authenticated inventory before its database mutation can be acknowledged. It contains a regional installation identity, random event UUID, one account UUID, request time and authenticated append sequence. Erasure additionally identifies the media UUID and its private object key. Deadline events identify the media/attempt UUIDs, original attempt creation time and expiry. Withdrawal records contain a database-clock cutoff. No names, email addresses, footage, post text or consent-document contents enter the journal.

The journal assigns region, owner, event identity and sequence itself; an event payload cannot override those fields. Object keys must remain under the exact regional account prefix with an opaque UUID and `upload`/`clean` suffix. Individual erasure queues those exact two variants, including a late previously signed upload; it never erases unrelated account files. Account deletion separately retains the broader orphan-prefix drain described in [RECOVERY.md](RECOVERY.md).

`MediaRecoveryState` and `ConsentWithdrawalRecovery` have no foreign key to media/account rows. Their minimized recovery metadata therefore survives removal of the current row and can protect an older restored row. These tables are private recovery state, not a public history or publication approval. Their safe physical expiry and the journal's pruning/custody scheme remain release work.

Original version-1 account events and their digests remain valid. Mixed histories replay in authenticated inventory order, not filename/UUID order. New writers and readers must be deployed together: old binaries cannot understand version-2 events and fail closed. Stop old API/worker processes before migration `202610180001_media_recovery`, then deploy matching images and validate the current independent journal. Do not replace it with a snapshot's older history.

## Connected actions

- Removing an unattached post upload durably records erasure inside the current account transaction before returning success. Storage failure prevents acknowledgement and rolls back database changes.
- The background worker has a writable journal mount and read-only journal key, and records independent erasure before deleting current objects or media rows, including withdrawn footage, expired evidence, account cleanup and abandoned uploads. A storage outage leaves the decision and retry job intact. Repeated retries do not append duplicate erasure events for the same terminal media UUID.
- Attaching physical-attempt evidence records its original 30-day maximum. Independent staff review records the seven-day finalization window, capped by the original 30-day limit and an already shorter deadline. Re-review cannot extend expired footage or repeatedly reset its retention window.
- An owner can appeal only with current recording permission, an unexpired attempt/deadline, a ready attempt-bound recording and current room/session access. A valid appeal extends retention only to 30 days from attempt creation. Erased media cannot be revived by an appeal, a review or a later deadline event.
- Guardian withdrawal checks the fresh parent, child, session and current relationship under account locks, then records the withdrawal before acknowledgement. Replay revokes consent and child sessions, hides sharing, withdraws score/card publication, removes physical eligibility and marks existing child footage for deletion. The recorded database-clock cutoff also protects recovery inventories from later overlooking the withdrawal. A newly created upload after the cutoff is a different object; fresh permission acceptance is still required before using child services.

Authorized privacy intent can survive an error response: once the independent record is durable, a subsequent database failure cannot cancel it. Reconciliation applies it later. This follows the same rule as confirmed account deletion; callers must not treat a timeout or rollback as proof that the request was cancelled.

## Retention and access

Replay processes deadline changes in append order and preserves the latest valid deadline. It does not erase from an intermediate expired review while replaying a later valid appeal. Terminal erasure always wins, regardless of a subsequent deadline event or an older database receipt.

Evidence access checks the original 30-day maximum, current attempt deadline, replayed deadline, terminal erasure and guardian-withdrawal cutoff before issuing a private link. A link's expiry is capped by the remaining evidence lifetime, with an explicit signing time; it cannot receive the ordinary two-minute window beyond the retention deadline. Fewer than one full second remaining denies the link. Ordinary post links retain their existing maximum of two minutes. Already delivered bytes cannot be recalled; production storage/version/lifecycle and access controls still need acceptance.

The worker uses the final replayed deadline for physical cleanup. Independent erasure is recorded before current-object deletion, and both object variants remain in bounded retries for late uploads. No S3 deletion happens inside a database transaction. Storage and database errors fail closed; operator monitoring and incident response must still be commissioned.
