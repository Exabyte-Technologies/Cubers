# Lesson interruptions and tutoring authority

Implemented 2026-10-20 for the online ordinary/last-layer lesson screen. Guided first-solve and physical practice retain their separate session controllers.

Tutoring checks current full-session, regional account, email, learning and guardian authority before generation and again before returning an explanation. These short transactions use the same ordered account/guardian, consent and session locks as other current-authority operations. No database locks remain held during provider work. Adult chat eligibility comes from current account data rather than the request's earlier policy snapshot. Revoked adult eligibility during generation withholds the pending reply, including a fallback, and asks the learner to reopen the lesson. A learner already ineligible for adult chat receives authored teaching. Guardian withdrawal also withholds a pending authored reply for a younger child. Published lesson identity/version checks still apply at delivery. This learning capability does not enable mainland social features or change release approvals.

The mobile screen allows one load, demonstration, tutoring request or checkpoint request at a time. Losing navigation focus or leaving the foreground invalidates that operation. Returning cannot revive its late success, error or completion callback, and its cleanup cannot unlock a newer operation. An interrupted initial load can retry on returning to the foreground; navigation refocus reloads the published lesson. A backgrounded demonstration keeps only the exact visible turn prefix and stops its timer. It does not automatically resume or earn progress. The learner can continue from the preserved position or reset after returning.

HTTP requests already admitted by the server can still finish there after the screen is backgrounded. Ignoring a stale UI callback does not undo an already verified checkpoint. Returning to the learning history refreshes persistent progress; no response from an old view may display a success for the new view. Account, region, learning-permission and chat-permission changes recreate the lesson view. Existing API request timeouts remain in force.

The selected shorter guide supplies both its demonstration and its bilingual step text. Each displayed demonstration turn immediately records its corresponding local move, rather than waiting for the whole sequence to finish. Input/guide changes, manual turns, undo and reset are blocked during an active demonstration or guidance/checkpoint request. Step indices are bounded when changing language.

Validation uses the actual shared demonstration runner against all 66 published alternatives and original drills for all four puzzles, exact reconstructed states at every frame, pending timer cancellation, blur/background callbacks and overlap rejection. Backend checks use real database authority changes, an actual lock wait and the local HTTP AI simulator for adult replies. Adult status/age, session deletion/scope/expiry, email, region, deletion and child guardian/consent revocation are covered. No live provider or credentials are used. Regional compiled-container checks additionally exercise current admission/delivery with AI disabled. Current results are recorded in [STATUS.md](STATUS.md).

Source tests and exported bundles do not establish native focus/background, accessibility, camera, Bluetooth or physical-device acceptance. Those original release requirements remain open.

The same current authority now covers ordinary/scanned/guided practice mutations, placement checks and new offline leases, including expiry after content/row waits and serialized cancellation. See [LEARNING-AUTHORITY.md](LEARNING-AUTHORITY.md).
