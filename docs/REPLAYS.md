# Private virtual solve replay

Updated 2026-10-20: complete approved 3×3 smart archives now share these private reconstruction controls with model/continuity labels. See [SMART-REPLAYS.md](SMART-REPLAYS.md) for telemetry limitations and acceptance scope. New smart attempts remain hardware-gated.

Implemented 2026-10-17. Profile → Private solve history → **Replay virtual solve / 回放虚拟还原** opens the saved owner's virtual race/daily sequence. Replay is a private study view, not a new attempt, progress submission, public share card or ranking result.

`GET /v1/me/replays/:id` requires a full current regional session and current learning permission. Mainland replay also requires the existing game-service approval gate. A foreign, missing, scanned, incomplete smart, rejected, provisional or non-race/daily record returns the same unavailable response; a malformed UUID is rejected. History advertises replay for eligible approved virtual records and complete approved smart archives. A saved smart replay does not activate Bluetooth or create an attempt; scanned physical attempts do not have a continuous move stream to reconstruct.

The server reads only the owned record's puzzle, mode, duration, record date, scramble and saved virtual events. A dedicated worker validates strict metadata, at most one hundred scramble turns and ten thousand events, contiguous sequence numbers, nondecreasing bounded timestamps, puzzle-specific legal turns and the final solved state. It returns only turn tokens and the needed metadata, excluding relative event timing, user/room identifiers, opponents, nonce, review reasons, recordings and evidence links. Unknown metadata is rejected. Corrupted legacy streams return an unavailable conflict instead of inventing a replay.

Worker validation is separate from first-solve planning. Each API process admits at most four active/queued replay jobs, runs one at a time, uses a three-second active deadline, and limits worker heap to 64 MiB old / 16 MiB young with a 4 MiB stack. Busy, interrupted and timed-out work fails without affecting original attempt status. Shutdown rejects waiting work. The complete source snapshot, status, account/session validity and current guardian learning permission are rechecked after asynchronous validation. Twenty replay requests per minute/account and existing regional HTTP limits apply. Responses are private/no-store.

The app validates and reconstructs the packet in batches of one hundred turns, yielding between batches and cancelling stale account/community/navigation loads. It keeps at most 101 geometric checkpoint states; seeking reconstructs at most 99 turns. A read-only 3D puzzle and labeled faces support start, previous, next and end controls, with a short move-text window rather than rendering ten thousand buttons. Camera-view rotation changes only presentation. Loading an earlier account's replay cannot render data in the current view.

Playback starts only after an explicit press, offers 0.5/1/2 steps per second and pauses on backgrounding, leaving the page, changing speed or seeking. Reduce Motion disables automatic playback and preserves manual stepping; the puzzle renderers also respect their reduced-motion setting. Playback timing is a study pace, **not original turn timing**. The server's saved duration is separately labeled; it is not an official competition time. Replaying cannot submit moves or award credit.

This private route does not persist replay data on the device, upload it, send it to AI or grant another account access. Separately prepared and approved anonymous snapshots now support [expiring replay-sharing links](REPLAY-SHARING.md). Existing account exports contain the underlying owned attempts; account deletion removes replay access and source records under the existing deletion policy. The response does not grant room membership or access to other participants, even when an archived shared container remains after another account's deletion.

Checks cover all four puzzles including wide/slice turns, rotations and Pyraminx tips; independent forward reconstruction at every short-sequence step; long ten-thousand-turn seek bounds; client cancellation; invalid/missing/replayed events and impossible saved outcomes. Database/API checks exercise owner/privacy/region/child boundaries, excluded inputs/status/modes, no progress, account deletion, worker admission/interruption/recovery/shutdown, and status/session/guardian changes during validation. Regional Docker tests reconstruct the actual recorded virtual solve in INTL and enforce the mainland game gate. Native bundles verify integration; fresh visual, device, reduced-motion and interruption acceptance remain release requirements.
