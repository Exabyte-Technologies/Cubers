# Attachment declarations and file labels

Implemented 2026-10-22. New post attachments can carry a separate author declaration. Supported declared and source-labelled JPEG/PNG and MP4/MOV files receive visible bilingual labels and embedded propagation metadata during private processing. This extends [image](IMAGE-AI-PROVENANCE.md) and [video](VIDEO-AI-PROVENANCE.md) source preservation. No media is sent to an AI provider and no origin is authenticated.

## Connected behavior

The composer has a separate switch for the next attachments, before selection/upload. The ordinary post switch remains separate because a post may contain AI-assisted text and an ordinary photo. Native and web uploaders send `aiDeclared` with the private upload reservation. The server accepts only a boolean and only for post media. Migration 45 adds a default-false field and a database trigger that prevents changing a file's declaration. Correcting a mistaken declaration requires removing the file and uploading a replacement. Old clients can omit the field; existing files acquire no invented declaration.

The declaration remains readable to authorized attachment viewers and in the owner's account export. A retained declared attachment forces the post disclosure on create/edit even if the post checkbox is false. It does not acquire a source-file claim: `aiSourceLabel`, `aiLabel` and the privately retained source metadata keep their existing meaning. Removing the attachment permits a fresh declaration and the normal fresh review. Ownership, regional access, blocking, guardian and moderator controls still apply.

A source claim retains its original class and supported fields. A declared file without a recognized source claim receives class `2` (possible generation) in its processed download metadata; unknown producer name and production identifier stay empty. Cubers supplies only its propagation name and opaque media ID. No signature or producer identity is verified or invented. Absent labels never establish human authorship. Recognized unsupported credentials and malformed/conflicting claims retain their existing refusal behavior.

## Visible output

The server adds an opaque dark footer with white Chinese and English wording. Three wordings distinguish generated, possible and suspected source classes. The footer extends the canvas instead of covering the picture. Dimensions stay bounded and even, and the rendered line height is at least five percent of the final shortest side. Very narrow images receive side padding so the text remains readable. Source pixels may be resized within the existing output boundary; output dimensions do not exceed 2048 pixels per side.

Labelled videos are normalized to silent H.264 at 30 fps, with the footer throughout the clip. Clips shorter than two seconds hold their last frame to make the label visible for two seconds. This behavior is disclosed before upload and in the bilingual privacy/user terms. Normal video orientation is applied; unsupported rotation/pixel-aspect geometry is refused. Processing retains its deadline and explicit file-only input restrictions, limits encoder threads and strips unrelated metadata/audio. Unlabelled media and private competition evidence keep their separate processing behavior.

Both image and video outputs are reparsed before upload/READY status, so loss or alteration of expected embedded fields fails processing. The visible and embedded labels are part of the actual downloadable file, rather than only an app overlay. Source fields, author declarations and generated propagation fields remain distinct. Attachment/account deletion and backup expiry policies continue to apply.

## Deployment and verification

Stop older APIs and media workers before applying `202610210002_media_ai_declaration`; restart matching API/worker images together before accepting new declarations. An older processor would ignore the new field. The migration does not enqueue/rescan existing READY files or publish posts. Existing stripped information cannot be reconstructed. Keep public/regional activation and hardware/ranking gates off pending their separate acceptance.
