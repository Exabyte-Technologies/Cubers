# Downloaded lessons and optional practice reminders

Updated 2026-10-28. Learn and Profile link to **Downloaded lessons / 已下载课程**. Every published course card has a download action, including first-solve teaching notes. An individual drill also has the action inside its lesson page. Active first-solve practice also offers a separate Download remaining guidance action between checkpoints. See [OFFLINE-FIRST-SOLVE.md](OFFLINE-FIRST-SOLVE.md). Downloads are explicit; there is no automatic background content download.

## Download and access rules

`POST /v1/courses/:id/download` requires the current authenticated regional session and learning/guardian permission. It accepts an empty body only, checks current publication, limits requests to 200 per account/hour, and returns a strict versioned packet containing authored bilingual teaching, course version, account/region scope and timestamps. The server caps access at the earlier of 24 hours or the current session expiry. The response is private/no-store. Downloading grants no progress, achievement, skill certification or match result.

Native copies use a bounded app-private cache file, with the session binding in platform SecureStore. The file contains authored teaching and the account identifier, plus a frozen checked color-state plan and source-practice metadata when remaining first-solve guidance is explicitly downloaded; no credential, profile biography, question, photo, recording or social content is written there. The browser implementation uses tab session storage and makes no claim to offline reload of the website itself. The native cache can survive restarting the installed app while the same saved session and time window remain valid; the operating system can evict cache files.

The library holds at most 200 lessons and 600,000 JSON characters (below the native two-megabyte file bound). Strict schema, puzzle notation, owner, region, session, version, time and size checks reject corrupt or mixed-scope content. Saving the same lesson replaces its prior version. Individual removal and clear-all are available. Writes are serialized; delayed old-account writes are discarded/erased before another account can use the library. Credential/preference writes are also ordered per key so delayed sign-out cleanup cannot erase a newer stored sign-in.

On opening the screen, local content appears first. A background authenticated `GET /v1/course-download-manifest` check removes withdrawn or changed versions when connected. A transport failure permits the existing time-limited copy; an explicit server denial does not. Publication versions must be incremented when authored content changes. The app removes cached access on sign-out, account/region/session changes, account deletion, invalid-session responses or detected learning-permission withdrawal. Remote revocation cannot reach a closed or disconnected device immediately; the offline window is the documented bound. Device clocks must be approximately correct; a one-minute future timestamp tolerance avoids rejecting ordinary clock skew. This local content check is not a substitute for server authorization.

The offline reader provides bilingual authored steps, original 3D virtual drills, puzzle-appropriate turns, undo, reset and a user-paced next-turn demonstration. It uses the same deterministic 2×2/3×3/4×4/Pyraminx logic. Ordinary first-solve course downloads contain notes. Downloading the current checked practice also supplies its remaining state-specific plan for local virtual/physical checkpoints across all four puzzles. Starting from a different state, replanning and saving server checkpoints require the connected first-solve flow. No offline activity is uploaded later, and there is no queue of completion claims, cloud AI requests or ranked results. Reconnect and complete a server-verified checkpoint to earn progress.

The signed-in connection screen also links to downloads, so a native cold start with an unavailable server can open a valid previously downloaded library without granting access to community, account administration or competition features.

## Optional local reminders

The native download screen includes an off-by-default reminder setting. The user chooses a local `HH:MM`, explicitly enables it, and completes the operating system's notification permission prompt. A fresh `/v1/me` check must confirm the same account, community and learning permission before enablement. No permission dialog appears merely by opening the app or settings screen.

The app schedules seven one-shot dates in local calendar time, using a quiet Android channel and no sound/badge request on iOS. Messages say only “Cubers” and a generic invitation to practice, in the chosen language. They contain no user name, age, school, region, lesson history or performance. Online account validation when reopening/foregrounding renews an existing preference without another permission prompt. Device timezone changes are reflected at the next renewal. Delivery can be delayed or suppressed by OS notification, battery or focus settings; exact delivery is not promised, and no exact-alarm permission is requested.

The preference stays in SecureStore on that device. Turning it off, signing out or deleting the account cancels only Cubers practice reminders and clears their displayed notifications/preference. A cold launch suspends scheduled alerts until the account is verified again. Different accounts/regions cannot inherit another account's setting. Permission denial, invalid preferences, partial scheduling failure or an account change during a permission prompt cannot leave partial old-account schedules. Remote withdrawal while the app remains closed/offline cannot cancel existing OS schedules immediately; schedules stop after seven days unless renewed.

No push token is obtained and no Expo/APNs/FCM push service is used by these flows. Android configuration disables Firebase messaging/installation auto-initialization and Analytics collection; iOS push entitlements and remote-notification background mode are omitted. The notification library includes optional push support, but this application uses its local scheduling APIs only. See the [SDK 55 notification API](https://docs.expo.dev/versions/v55.0.0/sdk/notifications/) and [Firebase automatic registration controls](https://firebase.google.com/docs/cloud-messaging/android/get-started). Browser reminders are unavailable and do not request browser notification permission.

## Verification and release limits

Pure local tests use injected storage and notification drivers; none sends a real notification. They cover all authored packet schemas, invalid algorithms/windows, version replacement, restart binding, expiry/future timestamps, malformed and mixed-owner files, publication pruning, late writes/sign-out, per-key credential ordering, calendar scheduling, explicit permission, finite renewal, denial/partial OS failure, corrupt settings, account-change races and cold-start suspension.

Integration checks cover authentication, regional/guardian boundaries, empty-body validation, current publication/version, private/no-store responses, session-expiry capping and no progress from downloading. Regional Linux Docker checks also download a first-solve packet without earned progress. The installed Android 36 emulator now passes an actual download, offline virtual solve, cold-start library access with the server stopped, Chinese rendering, manual turns, reconnection, notification denial, seven-date scheduling, cold-start suspension, renewal, one delivered notification and explicit cancellation. Synthetic server records remain byte-identical with no earned progress. See [the runtime acceptance record](OFFLINE-NATIVE-ACCEPTANCE.md). Android compilation, current platform bundles and unsigned iPhone packaging pass. Physical-phone and iPhone reminder delivery, revoked permission after scheduling, reboot/timezone/DST behavior, OS cache eviction, state-specific downloaded first-solve runtime and accessibility remain acceptance requirements.

English and Chinese privacy drafts describe these local stores, notification permission, finite scheduling and disconnected-revocation limits. Operator-specific legal/store review and the project's release gates remain required before publication.

## Alternate sequences

Published case downloads can include the optional [shorter guide](LESSON-ALTERNATIVES.md). The current client explicitly requests this extension; a legacy empty download request receives the original strict v1 lesson shape. Packet validation checks that an alternative solves the exact original setup in fewer turns, with bounded bilingual teaching and unique IDs. Selecting a guide resets only the local drill. Existing expiry, account/session binding, publication pruning and no-offline-credit rules still apply.
