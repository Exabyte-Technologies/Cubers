## Deletion recovery

Configured deletion requests are durably encrypted outside PostgreSQL before success, with current account/session/guardian checks under locks. Startup validates regional installation binding and present journal records before serving or starting a queue worker. Replay disables access and queues idempotent erasure; independent prefix markers catch objects whose media rows were lost in an older snapshot and repeated bounded drains catch late signed uploads. File-mode journaling is mandatory in production. An authenticated current inventory detects missing accepted files and snapshots bind its prefix. Complete storage rollback still requires independent custody. Real encrypted database capture/restore drills pass, but restored installations remain sealed pending media recovery, safe expiry and fresh commissioning; keep public release gated until RECOVERY.md and DATABASE-SNAPSHOTS.md requirements pass. The development-only storage emulator uses a legacy provider for synthetic cursor support; the API/worker runtime does not.
